# NGO reports in Environment

Sources: Auriga Nusantara, Trend Asia, Satya Bumi, WALHI. Raw data are private local
artifacts under `data/ngo/`, excluded from Git. No user chat history is stored by this pipeline.

## Import

Use `.venv/bin/python workflow/ngo_corpus.py discover`, then `ingest`, then
`.venv/bin/python tools/ngo_ocr.py` if Tesseract is installed, and finally
`.venv/bin/python workflow/ngo_corpus.py index`.
Run `.venv/bin/python tools/verify_ngo_corpus.py --publish` to check every passage's
source metadata, test retrieval for all four publishers, and activate the candidate.
Activation writes a small local pointer and retains the previous pointer for rollback.

The catalogue crawler follows observed category pagination only. Downloads validate
all redirect hosts, file size and PDF signatures. Failures are recorded, not silently
accepted. Repeat ingestion to resume; unchanged PDFs and extraction are reused.
The `--limit` option supports an initial round-robin pilot across publishers.

WALHI may reject the HTTP crawler. Public files can instead be downloaded via the
ordinary browser and inventoried in `walhi-browser-documents.json`; the explicitly
invoked `tools/import_walhi_browser.py` merges those verified files and sources.
The importer never copies browser authentication tokens into the downloader.

## Evidence contract

Every searchable passage has a publisher website URL, original PDF URL, SHA-256,
document ID, PDF page index, left/right side for spreads and a printed page label
when detected. Listed publication dates are not observation dates. Periods unknown
at ingestion remain unknown; the answer must read the actual passage for scope.

Exact duplicate PDFs are indexed once. Different language editions may both be
searchable but must not be counted as independent corroboration. Coauthors and
primary data providers must be attributed based on the document, not inferred from
the website hosting it.

Extraction is page-based with local pdfplumber. Sparse/image pages are marked for
OCR or visual review; optional local Tesseract OCR requires mean word confidence
of at least 80 and enough text. This is a readability gate, NOT independent accuracy
verification. Charts, maps and tables are not certified for computation. Some
multi-column text may require manual correction. Numeric summaries must use
complete sentences with their units and scope; no computed statistics from these PDFs.
Text outside the visible page is excluded, including neighbouring-page text retained
by some PDF exporters. Extraction and OCR use three local workers; per-document
results are cached so interrupted imports can resume.

## Search and answers

Local FastEmbed multilingual MiniLM (384 dimensions, 128 token input window).
Passages are split to fit the tokenizer; embedding inference does not send report
contents to an embedding service. Qdrant NGO collections are versioned separately
from GFW collections; indexing does not delete or overwrite GFW data.

`candidate.json` records an indexed candidate. `active.json` is published only after
retrieval and source tests pass. Keep prior collections for rollback. No collection is
deleted automatically. Search uses explicit publisher filters, semantic scores and
page diversity. It is bounded retrieval, not an exhaustive inventory or proof of absence.

Environment routes explicit report/NGO questions and selected narrative topics into
this path. Existing GFW statistical questions retain their exact numeric retrieval.
Narrative forest/mining/plantation questions can include a bounded GFW tree-cover-loss
series when a single exact administrative area and complete requested years match
the local catalogue. Islands, villages and subdistricts are not substituted with a
containing district. Report findings keep their own local or regional scope.

The existing chat AI makes bilingual search queries and synthesizes retrieved pages;
therefore relevant excerpts and the question ARE sent to the configured AI provider.
Evidence and original passage IDs are checked in code. Sentence windows are taken
from the locally extracted page; the AI selects IDs rather than reproducing quotes.
Actual opening page text and report titles accompany passages as scope context.
Unknown passage IDs, unsupported numeric values and ungrounded place names are
rejected. Decimal comma/point translation is allowed without changing values.
An additional AI review
checks support for findings and conclusions. These checks do not guarantee factual
correctness. Invalid citations or unsupported answers abstain. External report text
is treated as untrusted evidence, never instructions. URLs are taken from the stored
manifest only, never generated by the model. Findings explain the report in Indonesian
and retain page citations; original passages remain internal supporting evidence.
Numeric prose findings can be shown in a table. This does not certify arbitrary
PDF tables or graphs, and survey response percentages are not added together.
For combined questions, up to three retrieved PDFs are examined independently.
Each report finding is checked for support and topical relevance, not required to
answer the entire multi-source question or supply GFW numbers. This distinguishes
faithfulness of a finding from completeness of the final answer. A final synthesis
combines accepted report findings with GFW while
keeping geography, period, observation and attribution distinct. No causal link is
inferred solely from GFW changes. Explicit multi-district scope is preserved in a
short context note, with the supporting PDF pages included in the source locator.
Summary metric values must occur in the accepted findings or GFW table; additional
metadata cannot silently introduce a measure excluded from the displayed findings.
OCR-derived passages have an explicit note.
Public answers show one Source and one
Download link per used PDF. Claims retain the existing verdict label.
Findings use short document numbers such as [1]; full titles and PDF pages appear
in the source footer. Exact per-finding page/printed-page/side locators remain in
`finding_citations`. A numeric table from one PDF names that source once in its
caption; tables spanning PDFs use short source numbers per row. Saved answers
receive the same presentation change without regenerating their findings or values.

## Answer layout

Report findings are grouped by hosting organization (`finding_groups`), with direct
bullet points and a numeric table for each group when traceable prose values exist.
Hosting organization is a source label, not an inferred authorship claim. Survey
responses, allegations, estimates and projections keep their actual qualifications.
The claim verdict and its reason stay at the top. GFW contextual findings precede a
final `Kesimpulan` synthesizing the accepted sources; material limitations belong in
that short synthesis. An editorial warning is optional, for a concrete causal,
program/policy or overgeneralization issue, with useful follow-up questions.
The browser display and copied answer use this same order. Historical answers are
reorganized using their existing numbered citations without regenerating facts;
ambiguous old findings are not assigned a guessed source.

There is no place-specific exception for Kabaena. Requested finer scopes are
recognized from location types in the question and source titles/page text. A
separate, explicitly stated administrative GFW scope can accompany an island or
village report as wider context. It must match the local catalogue exactly; the
pipeline never infers an enclosing district. A reference such as "kabupaten ini"
can resolve to one explicitly named, preceding district in the same question;
multiple possible antecedents are left unresolved. Query-time evidence checks
complement the versioned corpus rebuild described below.

Report numeric tables preserve full thousands separators and magnitude words
(e.g. juta) from supported prose. Plans/projections/threatened area must retain
those qualifications in the finding and table label rather than become observed
conversion. The final synthesis does not append a second generated context block;
explicit cross-boundary scope and OCR notes remain separate, bounded evidence notes.

## Full enriched rebuild (v3)

The v3.4 repair adds versioned PDF reading order and source-anchored model-method
context. Prepare a separate text snapshot with
`.venv/bin/python tools/prepare_ngo_layout.py`, then build with
`.venv/bin/python workflow/ngo_reindex.py --pages-root extractions/ngo-pdf-v3
--reuse-context v3/<previous-build-id> --threads 4` (one command).
The snapshot preserves OCR parts and original text where a conservative two-column
prose detector cannot identify a reading-order correction. Every detected correction
retains the same word tokens. Original PDFs and prior page text remain untouched.
`pages_root` is included in the build signature and active pointer, and all retrieval,
source checks and edition verification read from that same snapshot. The
`--reuse-context` option reuses vectors only for the same model and identical encoder
input; changed text is embedded again.

Each retrieved finding may include bounded methodology passages from source pages
with original offsets and page numbers. Nearby passages and method introductions
are retained separately, so both an executive summary and a later conclusion can
refer to the original method regardless of page order.
A separate method review handles findings that the relevance review has not already
identified as model results. Review must match the method to the
specific result, project and area; presence of a model elsewhere in a report does not
make the entire report a simulation. Accepted model results retain that qualification
and cannot establish an observed causal outcome. Referenced method pages are included
in the source footer. Relative source periods remain anchored to the report, rather
than silently moving to the current date. Numbered subsections and wrapped place
names are handled without place-specific exceptions.

Run `.venv/bin/python workflow/ngo_reindex.py --pilot` and
`.venv/bin/python tools/verify_ngo_reindex.py --pilot` for the cross-publisher
sample. Then run `.venv/bin/python workflow/ngo_reindex.py` for the entire extracted
corpus, followed by `.venv/bin/python tools/verify_ngo_reindex.py --publish`.
The existing `ngo_corpus.py index` and `verify_ngo_corpus.py --publish` entrypoints
also route new candidates to this pipeline. Existing v2 data stay readable.

A rebuild writes only a new `cekdata_ngo_v3_*` Qdrant collection and an immutable
build directory under `data/ngo/v3/<build-id>/`. The active pointer changes only
after full verification. Interrupted builds reuse their actual stored point IDs;
no collection is deleted. Publication retains both `previous-active.json` and a
versioned copy in `active-history/`. To roll back, restore the prior published
pointer; there is no need to regenerate vectors or restart the local server.

Each child preserves exact source-page character offsets and links to a larger
parent made of consecutive source sentences. Parent and child neighbours keep
their own page/side locators; following a link never changes a quote's origin.
Children target 100 tokens. An anchored heading/place hint is added only when the
complete input remains within 126 tokenizer tokens. No child content is silently
truncated to fit the encoder. Every non-whitespace character on every readable
page-part is covered. Sparse/unreadable parts remain in the document inventory.

Metadata are extracted locally by explicit, auditable rules, not filled with
model guesses. This is a source-indexing operation, not independent verification
of the report or every inferred entity:

- `metadata`: mentions actually contained in the child span.
- `context_metadata`: separately labelled parent mentions; never copied into direct geography.
- Locations retain source spelling, type, recognition method, role candidate,
  resolution status and exact quoted character offsets. GADM 4.1 names/IDs refer
  to the existing GFW boundary snapshot, not automatically to current boundaries.
  Learned names without an administrative reference remain unverified; ambiguous
  names are not forced into a district. Reference parent IDs are catalogue facts,
  not proof that an island/village finding covers its enclosing district.
- Publication dates stay separate from anchored observation/projection/reference
  year mentions. Unknown observation periods remain null.
- Quantities preserve original separators, units, magnitude words, sentence
  context, respondent labels when explicit, and projection/threat/estimate/survey
  markers. They are not computed or promoted from unverified table cells.
- Topic and company-name candidates, language heuristics, heading candidates,
  explicit credit lines, extraction/OCR confidence and quality flags are retained.
  Hosting organization is never silently assigned as the author.
- `document-relations.json` flags possible language editions only when publisher
  filenames differ by explicit language tokens. It does not assert translation
  identity from similar titles. Other edition relationships stay unknown.
- `gazetteer-origins.json` retains typed-name source examples and reference-file
  checksums so dictionary recognition can be audited, including sparse-page origins.

Search combines normal semantic retrieval with an additional metadata geography
channel. Geography and topic evidence affect ranking without excluding every
regional context. Source diversity does not force an unrelated publisher. The
answer model receives original prose windows and explicitly labelled context
metadata; existing citation/number/scope/claim reviews remain in place. The four
verdict labels, grouped findings, source/download links and browser-only chat
history contract remain unchanged.

Verification checks all child IDs and complete Qdrant payloads against the local
candidate, original PDF checksums, source spans and metadata anchors, full readable
page coverage, parent/child links, token budgets, exact source URLs and retrieval
cases with and without named publishers. The build contains per-document progress,
coverage, document metadata, parents, child records, source relationships and the
verification report. Passing these checks does not certify real-world geography,
causation, report truth or arbitrary PDF tables/figures.

## Cross-region live checks

Live questions cover Rempang (displacement/livelihoods), Pundenrejo in Pati
(land conflict), Muara Laboh in Solok Selatan (water/agriculture), Ketapang
(pulpwood/customary rights plus GFW), Teluk Bintuni (LNG/coastal livelihoods),
and Ujung Kulon (rhino conservation). Test responses and screenshots are kept
under `tmp/ngo-varied-live/`; these local development fixtures are not a new
server-side store of user conversations.

The checks exposed several general retrieval/reading issues:

- Narrative impacts/risks now enter report retrieval without requiring a
  publisher or a commodity keyword. In Environment, a concept that does not
  match the numeric catalog can also fall back to reports. Explicit GFW and
  MapBiomas requests preserve their own missing-data behavior.
- Learned, unverified names do not create geographic filters merely through
  capitalization. Bare common words are excluded unless the query contains a
  locative/type signal; a species' geographic adjective is not itself a requested
  study location. Known boundary names remain usable.
- Actual child/parent matches to the most specific requested geographic type
  take priority. Publisher diversity cannot force a purely national/other-region
  publisher ahead of relevant local reports.
- Prose passages retain preceding original sentences as `support_context`.
  Extraction and review must preserve the location and projection status of
  numerical findings. A figure projected for one region must not be attributed
  to the project in the question.
- A model's comment that no evidence was found is not a cited report finding.
  Survey attribution and typed place spelling are checked before accepting
  synthesized conclusions. Unknown GFW causes cannot be restated as proof of
  other causes.

These are read-time improvements over the same published v3.3 collection; no
original pages or embeddings were overwritten. Ujung Kulon remains a partial
live answer: the tested question returned conservation funding/governance
evidence but did not adequately cover the requested poaching aspect. Focused
tests do not establish completeness or general model accuracy.

## Claim evidence and outcome checks

`ngo_evidence_policy.py` separates faithful quotation, geographic/activity fit,
and evidence sufficient for a verdict. Each extracted finding is checked against
the original question and its own source passages. Other regions, different
activities (for example timber/energy plantations versus oil palm), unknown
scope, and comments about missing search results cannot become local findings.
Regional or general context can remain visible without becoming decisive proof.

Confident verdicts must cite accepted finding IDs with a matching support or
contradiction role and an observed/reported outcome, rather than interpretation,
projection or risk alone. A separate claim assessment names supported and missing
components. `Benar` needs complete support, including causation when claimed;
`Salah` needs direct counterevidence; `Sebagian benar` needs an actually supported
component of the claim. The synthesis cannot override this decision. Specific
income, poverty and employment claims also require the finding to address that
outcome: a static job share cannot establish a household income trend. NGO
observations can be decisive when appropriate; the rules do not require BPS.

Search plans request neutral evidence about the claimed outcomes. Welfare claims
about plantations/industry use report retrieval instead of stopping at land-cover
statistics. Bounded exact-location and within-document searches supplement vector
similarity; the latter only changes ranking and never inherits geographic facts
into a finding. Reference-list pages are filtered using original page text while
ordinary body pages with footnotes remain eligible. GFW contextual geography must
match compound administrative names even without a province/district prefix.

The pre-change ten-claim evaluation is in `tmp/claims-welfare-live/`; repeat
development checks are in `tmp/claims-welfare-fixed/`. These are synthetic test
claims, not a server-side archive of user chat. Model relevance checks remain
fallible; passing these cases does not certify the corpus, causal identification,
all geographic relationships or general fact-checking accuracy.

Claimed amounts are removed from one neutral search channel so an incorrect
percentage does not filter out the source's actual percentage. Explanations may
compare the claimed and observed figures; findings still require source-only
numbers. The structured fit review replaces the older per-report yes/no answer
review, which could discard counterevidence merely because it did not agree
with a claim. Numerical extraction gets one bounded repair attempt when needed.

Table labels are checked separately (`measure_supported`); an unsupported label
does not turn a market share into an environmental-impact statistic. Broader
regional findings are marked in the prose and excluded from local numeric tables.
Synthesis also checks each organization's stated geography against its own source
passages, rather than borrowing place names from GFW. Missing-evidence asides can
be removed while retaining the preceding actual finding.

The varied-question audit also checks exact supporting sentence IDs, rather
than accepting a nearby caption as geographic proof. Numeric ranges spanning
several named places must retain those places. A village named in a photograph
cannot locate the findings in the next numbered prose block. Pages beginning
mid-sentence receive the preceding original page's ending, with an anchored
continuation subject; search metadata and report titles cannot replace it.
These are read-time checks on original archived pages; they do not change the
indexed chunks or infer new geographic boundaries.

Synthesis retains the original geographic scope beside quoted numbers and
keeps income bounds such as “up to”. Before/after income answers must include
both values when accepted findings supply them. The fallback retains that
pair rather than repeating only the first finding. Unsupported superlatives
cannot drop their original comparison sector. Live cases and development
attempts for this repair are stored in `tmp/varied-answer-repaired/`.
